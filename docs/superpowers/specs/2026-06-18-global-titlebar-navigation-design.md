# 全局标题栏与导航控制设计

## 背景

当前桌面应用同时存在 Windows 原生黑色标题栏和应用内空置标题栏。原生标题栏左侧只展示 `TypeDance` 标识，右侧只能展示系统窗口按钮；主题切换和面板显隐控制位于下方应用标题栏，造成顶部视觉割裂，也无法形成统一的全局导航入口。

本次改动将桌面窗口切换为自绘标题栏，用应用主题色统一窗口顶部与正文区域，并重新安排全局导航、主题、窗口控制和 AI 面板显隐入口。

## 目标

- 删除原生标题栏中的 Logo 展示区域，用全局控制区替代。
- 左上角依次展示左侧导航显隐、返回、前进按钮。
- 返回与前进遵循应用内访问历史；对应方向没有历史时按钮置灰且不可点击。
- 主题切换按钮放在最小化按钮左侧，并使用竖线与左侧功能区或窗口控制区形成视觉分隔。
- 最小化、最大化/还原、关闭按钮保留标准桌面窗口行为。
- 将右侧 AI 面板显隐按钮移到 AI 聊天区域标题右侧。
- 顶部背景、边框和前景色使用应用主题变量，不再显示纯黑色标题栏。

## 非目标

- 不修改工作台三栏的业务数据流、会话逻辑或画布逻辑。
- 不调整左侧导航、画布和 AI 面板的宽度策略。
- 不新增旧标题栏与新标题栏并存的兼容分支。
- 不改变 Web 浏览器环境下页面路由结构。

## 方案选择

采用完整自绘全局标题栏：在 Tauri 主窗口关闭原生装饰，由 React 渲染统一标题栏。该方案可以精确控制按钮顺序、主题色、拖拽区域及 AI 面板控制位置。

未采用以下方案：

- 保留 Windows 原生标题栏：无法向 Logo 和系统窗口按钮区域插入自定义 React 控件。
- 使用标题栏 overlay：Windows 下按钮占位与拖拽区域更复杂，难以稳定还原目标布局。

## 组件边界

### Tauri 窗口配置

`apps/desktop/src-tauri/tauri.conf.json` 关闭主窗口原生装饰。能力配置允许当前窗口执行拖拽、最小化、最大化/还原和关闭操作。

### 全局标题栏

在 Web 应用壳层增加独立的全局标题栏组件，由 `SiteLayout` 统一渲染，职责包括：

- 左侧导航栏显隐；
- 应用历史返回与前进；
- 主题切换；
- 窗口最小化、最大化/还原和关闭；
- 窗口拖拽与双击最大化/还原。

组件只负责桌面壳层控制，不承载 Resume Pack、Workspace、Conversation 等业务概念。窗口 API 封装在单独的 Tauri 适配层中；非 Tauri 的 Web 测试环境提供安全的无操作边界，不伪造桌面业务行为。

### AI 面板标题栏

`AgentChatPanel` 标题右侧接收并渲染 AI 面板隐藏按钮。`RevisionWorkspacePage` 继续通过 `RevisionWorkspaceChromeContext` 读取和更新显隐状态，不把 AI 面板状态下沉到 Tauri 层。

AI 面板隐藏后，在工作台最右侧同一标题高度保留窄的恢复入口，用于重新显示 AI 面板。恢复入口属于工作台布局，不进入全局标题栏。

## 布局与视觉

全局标题栏高度约为 36px，使用 `bg-background`、`text-foreground` 和 `border-border`，与应用浅色/深色主题同步。

标题栏从左到右为：

1. 左侧导航显隐按钮；
2. 返回按钮；
3. 前进按钮；
4. 可拖拽空白区域；
5. 主题切换按钮；
6. 竖向分隔线；
7. 最小化按钮；
8. 最大化/还原按钮；
9. 关闭按钮。

按钮使用现有 shadcn `Button` 的 ghost/icon 形态和 Lucide 图标。关闭按钮悬停时可使用系统常见的危险色反馈，其余窗口按钮沿用主题前景色和弱悬停底色。

原 `SiteLayout` 中位于内容上方的空置 header 删除，正文直接占用标题栏以下剩余高度，避免双层顶部空间。

## 交互规则

### 历史导航

- 返回和前进使用浏览器 History API，与 React Router 的页面访问历史保持一致。
- 组件维护当前 history entry 的轻量索引和边界状态，并监听 `popstate` 更新按钮可用性。
- 新导航发生后同步刷新历史状态；不存在目标历史时不执行导航。
- 页面首次打开且无可用记录时，返回和前进均置灰。

### 窗口拖拽

- 只有标题栏空白区域可拖拽。
- 所有按钮、分隔线及交互元素不得触发拖拽。
- 双击拖拽区域切换最大化/还原。

### 面板显隐

- 左侧导航显隐按钮始终位于全局标题栏左侧。
- AI 面板可见时，隐藏按钮位于 AI 标题右侧。
- AI 面板隐藏时，工作台右缘展示恢复按钮；点击后恢复面板，标题内按钮随面板重新出现。

## 错误处理

- Tauri 窗口调用失败时不阻断页面渲染；事件处理函数捕获异步错误并在开发环境输出可定位信息。
- Web 环境不调用 Tauri 窗口 API，标题栏布局仍可渲染和测试。
- 历史边界状态不确定时采用保守策略：禁用对应导航按钮，避免跳出应用或进入无效记录。

## 测试与验证

### 组件测试

- 验证全局标题栏按钮顺序、标签和分隔线位置。
- 验证无历史时返回/前进禁用，有历史时可用并调用正确方向。
- 验证左侧导航显隐状态与按钮状态一致。
- 验证主题切换仍更新根节点主题类和本地存储。
- 模拟 Tauri 适配层，验证最小化、最大化/还原、关闭调用。
- 验证工作台不再渲染旧的顶部控制区。
- 验证 AI 面板按钮位于标题右侧，并能隐藏；隐藏后恢复入口可重新显示面板。

### 工程验证

- 运行 Web 相关 Vitest 测试。
- 运行 `pnpm --filter @typedance/web build`。
- 运行 Tauri Rust `cargo check`。
- 在桌面开发模式下人工验证拖拽、双击最大化、窗口按钮、主题色和三栏显隐。

## 架构边界检查

本次改动属于 Frontend 与桌面壳层：React 管理视觉与路由历史，Tauri 只提供确定性的本机窗口能力。不会向 Harness Core、TS Agent Host 或 Python Sidecar 引入窗口、主题、路由或面板概念；AI 面板状态仍是前端展示状态，不进入 Agent 编排层。
