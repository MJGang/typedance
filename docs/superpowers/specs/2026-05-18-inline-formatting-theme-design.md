# 选区格式与主题设置设计

## 背景

当前模板样式以 `TemplateStyleConfig.blocks` 为唯一来源，右侧设计面板会跟随选区在 `heading1`、`paragraph`、`bulletList` 等块类型之间切换。这适合统一模板调参，但不适合真实编辑场景：用户经常只想让某几个字、某一行或某个条目更突出。

后续样式单位统一使用 `px`，不再新增 `pt`。

## 产品方向

模板保留，但角色从“唯一样式来源”调整为“全局默认主题”。局部样式由编辑器选区工具承担。

- 顶部工具栏或浮动工具条：调整当前选中文本或当前块。
- 主题设置：调整整份简历的默认外观，例如模板、字体、主色、字号密度、页面边距。
- 右侧默认能力：优先服务 AI、建议、诊断等上下文任务，不再常驻一个会跟随选区变化的设计菜单。

## 第一阶段范围

第一阶段不追求完整 Notion/Yuque 式排版能力，先建立正确的职责边界和数据通路。

1. 将右侧设计入口弱化为主题设置，不再表达“当前选中块样式编辑”的主入口。
2. 在编辑器工具栏中承载局部格式能力。
3. 局部格式写入 TipTap 文档结构，确保保存、预览、HTML/PDF 导出一致。
4. 模板默认样式继续作为 fallback，局部格式只覆盖被用户显式修改的属性。

## 数据模型

块级默认样式仍使用：

```ts
TemplateStyleConfig.blocks: Record<BlockType, BlockStyle>
```

局部样式写入文档节点或 mark：

- 选中文本样式：优先使用 mark，例如 bold、italic、textStyle/color 等。
- 当前段落/标题/列表项样式：使用节点 attrs，例如 `styleOverride`。

渲染优先级：

```text
主题默认样式 < 块级局部覆盖 < 文本 mark 样式
```

## 编辑器体验

顶部工具栏负责当前内容：

- 加粗、斜体。
- 标题、正文、列表切换。
- 颜色、字号、清除格式作为后续扩展。
- 对齐、块级间距等属于“当前块”能力，可写入节点 attrs。

主题设置负责全局默认：

- 模板/主题选择。
- 主色、字体、默认字号、密度。
- 页面边距。
- 一键清除文档局部覆盖。

## 渲染与导出

所有渲染端必须识别同一份 TipTap JSON：

- 工作区编辑器：通过 TipTap attrs/marks 即时展示。
- 前端预览：将 attrs/marks 转为 inline style 或稳定 class。
- HTML/PDF 导出：sidecar 渲染时读取 attrs/marks，保证导出不丢样式。
- `packages/resume-renderer`：同步实现，避免预览与导出分叉。

## 测试要求

- contracts：覆盖新增局部样式字段或 mark attrs 的 schema。
- web：覆盖工具栏应用局部样式、保存 JSON、重新加载仍保留。
- renderer：覆盖局部样式优先于主题默认样式。
- sidecar：覆盖 HTML/PDF 渲染包含局部样式。

## 非目标

- 不支持“自动换行后的视觉第二行”单独设置样式。
- 不新增 `pt` 单位。
- 不把所有模板能力移除，模板仍是全局主题来源。
