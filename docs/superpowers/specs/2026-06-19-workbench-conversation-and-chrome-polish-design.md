# 工作台对话与界面边界优化设计

## 目标

让修订工作台的新对话生命周期符合真实使用语义，并统一左侧导航、应用顶部栏、工作区标题栏和 AI 面板之间的视觉关系。

## 交互设计

### 新对话

- 点击任一“新对话”入口时，只进入本地空白草稿状态，不调用创建对话接口。
- 空白草稿没有标题，左侧对话列表也不显示占位项。
- 用户首次发送有效消息时，AI 面板先创建对话，再发起 run；创建成功后将该对话设为当前对话并刷新左侧列表。
- 用户在发送前切换到历史对话，直接放弃空白草稿，不产生需要清理的后端记录。
- 已存在但名称和预览均为空的历史记录不再显示“新对话”兜底标题，避免把空标题误解为正式名称。

### 左侧对话列表

- 已置顶标识继续保留，但图钉缩小到紧凑尺寸，避免压过标题和时间信息。
- 菜单内的置顶操作图标维持菜单标准尺寸，只调整列表行中的状态图钉。

## 视觉设计

- 左侧导航只保留与主工作区之间的右边框，移除顶部、底部以及设置菜单上方的横向边框。
- 应用顶部栏在工作台路由使用与左侧导航一致的 `bg-sidebar`；其他页面维持现有背景，避免无关页面被连带改变。
- 工作区标题栏保持自身底部分隔线，并在左侧导航可见时增加左上角、左下角圆角，使其与同色顶部栏和导航形成连续外壳。
- AI 面板消息区域与输入区域之间移除横向分隔线；输入框自身的圆角边框继续保留，用来表达输入控件边界。

## 实现边界

- `RevisionWorkspacePage` 负责“开始空白草稿”和当前对话选择状态。
- `WorkbenchSidebar` 只触发开始新草稿，不直接创建后端对话。
- `AgentChatPanel` 沿用现有的首次发送时创建对话逻辑。
- 本次只调整 Frontend 展示与交互，不修改 Harness Core、TS Agent Host 或 Python Sidecar 的职责和接口。

## 验证

- 组件测试覆盖：点击新对话不调用创建接口、不新增列表项；首次发送才创建并选中对话。
- 组件测试覆盖：工作台顶部栏背景、标题栏圆角、导航与 AI 输入区分隔线的关键 class。
- 运行 revision 相关 Vitest 测试和 `@typedance/web` 构建。
- 在浏览器中检查左右面板展开状态下的边界连续性、图钉尺寸及空白草稿行为。
