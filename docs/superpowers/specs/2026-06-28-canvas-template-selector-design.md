# 画布模板选择器设计

## 目标

在修订工作台的画布顶部工具栏中增加模板选择下拉按钮。用户可以从系统当前已配置的官方模板和自定义模板中选择一个模板；选择结果按文档持久化，重新打开文档后继续使用同一模板。画布预览与 PDF、HTML 导出必须使用同一份模板样式配置。

## 架构边界

- `Frontend` 负责加载模板列表、展示当前选择、提交模板切换，并把解析后的模板样式同时交给画布和导出流程。
- `Python Sidecar` 负责保存文档的 `template_id`、创建文档时设置默认模板，以及删除模板时维护文档引用完整性。
- `Harness Core` 与 `TS Agent Host` 不参与模板选择。模板属于确定性的业务文档数据，不属于 Agent 编排。

## 数据模型

`Document` 增加必填字段 `template_id`：

- 新文档默认使用经典 A4 模板 ID。
- 数据库迁移一次性为现有文档写入经典 A4 模板 ID。
- 文档更新接口允许更新 `title` 和 `template_id`，未提交的字段保持原值。
- 选择结果只保存模板 ID，不复制完整模板配置。

模板样式仍由现有模板样式存储提供。文档加载后，前端通过 `document.template_id` 从当前模板列表中解析唯一的 `TemplateStyleConfig`。模板配置后续被编辑时，引用该模板的文档自动使用最新已保存配置。

删除自定义模板时，Sidecar 在删除模板配置的同一业务操作中，把引用该模板的文档一次性切换到经典 A4。运行时代码不保留缺失模板的 fallback 或双轨兼容逻辑。

## 前端交互

模板选择器位于修订工作台画布顶部工具栏的操作区，使用现有 shadcn/ui `Select`：

- 触发器显示当前模板名称并提供明确的“选择模板”可访问名称。
- 下拉内容分为“我的主题”和“官方主题”两个分组。
- 当前模板由受控 `value` 标记。
- 模板列表加载期间禁用选择器。
- 切换模板时调用文档更新接口；保存成功后再更新本地文档状态和画布样式。
- 保存失败时保留原模板，并显示错误提示。

模板加载失败或文档的 `template_id` 无法解析时，页面显示明确错误并禁用模板选择和导出，不静默应用其他模板。

## 单一数据流

页面加载时并行获取工作区和模板样式列表，合并官方模板定义与已保存样式，得到可选择模板集合。根据 `workspace.document.template_id` 解析：

```text
document.template_id
        |
        v
selectedTemplateStyle
        |
        +--> DraftCanvas.templateStyle --> generateWorkspaceCSS --> 画布预览
        |
        +--> export payload.templateStyle --> PDF / HTML 导出
```

画布预览和导出不得分别读取默认样式，也不得各自维护模板状态。模板切换只改变视觉样式，不修改 `doc_json`、页边距或编辑历史。

## 错误处理

- 模板列表读取失败：显示“无法加载模板”，禁用选择器和导出。
- 模板 ID 无法解析：显示数据错误，禁用选择器和导出。
- 模板切换保存失败：保持原选择和原画布样式，使用 toast 提示失败。
- 导出期间继续沿用触发导出时的 `selectedTemplateStyle`，避免预览与导出参数来自不同状态。

## 测试

- Contracts：验证 `Document.template_id` 和文档更新请求。
- Sidecar：验证迁移、创建文档默认模板、更新模板 ID，以及删除使用中模板时重置引用。
- 前端：验证模板列表加载、当前模板显示、模板分组、切换成功与失败。
- 一致性：验证 `DraftCanvas.templateStyle` 和导出 payload 使用同一个已选模板配置。
- 回归：验证切换模板不修改 `doc_json` 和页边距。
- 完成验证：运行相关 Vitest、Sidecar pytest、完整 Web build 和 shadcn 项目信息检查。
