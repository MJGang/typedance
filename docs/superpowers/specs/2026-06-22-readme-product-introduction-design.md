# TypeDance README 产品介绍设计

## 目标

重新生成仓库根目录 `README.md`，将其作为 TypeDance 的对外产品介绍页，而不是开发者接入文档。

README 需要让第一次接触 TypeDance 的读者快速理解：产品服务谁、解决什么问题、核心体验是什么，以及它与普通 AI 简历生成工具有何不同。

## 目标读者

- 希望了解 TypeDance 产品价值的潜在用户
- 关注 AI-native 文档产品的产品与设计从业者
- 希望快速判断项目方向的外部合作方或项目访客

## 产品定位

TypeDance 是一个以简历改稿为首个场景的 AI-native 职业文档工作台。

产品不以“一次生成一份简历”为目标，而是围绕用户资料、文档问题、修改建议、事实证据和最终交付稿建立持续、可理解、可控制的改稿过程。

## 内容结构

README 按以下顺序组织：

1. 产品名称、定位和一句话价值主张
2. 用户在传统简历修改过程中的核心困难
3. TypeDance 的产品方法：结构化改稿，而非一次性生成
4. 核心产品体验
   - 导入或创建基础简历
   - 在 Revision Workspace 中阅读、修改和审阅文档
   - 通过 Resume Pack 组织简历语义与改稿规则
   - 使用 AI 对话和本地资料补充上下文
   - 调整版式并导出可交付文档
5. 一条从输入资料到完成文档的典型使用流程
6. 产品原则与适用人群
7. 当前阶段和后续产品方向

## 表达方式

- 使用中文，语气清晰、克制、有产品感
- 先讲用户问题和产品体验，再介绍产品概念
- 使用短段落和有限列表，避免堆砌内部名词
- 对 `Resume Pack`、`Revision Workspace` 等名称给出面向用户的解释
- 只描述当前产品中可以找到依据的能力；愿景与已实现能力明确区分

## 明确排除

README 不包含以下内容：

- 系统架构、服务分层或数据流
- 代码目录、包职责或技术栈
- 安装、开发、构建、测试和端口说明
- 内部实施计划、历史兼容方案或工程迁移过程
- 面向贡献者的代码协作指南

这些信息可以继续由仓库内现有工程文档承载，不进入本次对外产品介绍。

## 真实性边界

- 不把目标蓝图直接描述成已交付能力
- 不使用“全自动”“一键完成”“保证通过”等不可验证承诺
- 不将 TypeDance 简化为聊天框或通用文本编辑器
- 不把岗位 JD 描述为创建简历的唯一入口
- 明确当前以简历场景为起点，并保留向更多职业文档扩展的产品方向

## 验收标准

- 新读者在首屏即可理解 TypeDance 是什么
- 产品价值、核心体验和典型流程完整连贯
- 产品介绍与仓库当前产品文档和界面能力一致
- 全文不出现架构、代码、技术栈或开发命令
- 所有仓库内链接均有效，Markdown 结构清晰
