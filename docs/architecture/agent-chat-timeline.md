# AI 对话时间线与运行中补充输入

## 用户可见行为

- 任务运行时仍可输入和发送文字、引用、图片与文件；停止操作独立保留。
- 补充消息发送成功后立即进入当前对话，并在模型尚未接收时标记“将在下一步处理”。停止后仍未处理的输入标记“本次未处理”，保留在历史中供后续任务参考。
- AI 文字按模型响应与事件顺序分段，工具摘要穿插在文字之间；连续工具调用合并为一行，点击展开记录。后续文字不会拼接到前一段“结论”。
- 当前阶段显示思考、执行或回复；任务结束后移除活动指示。已结束的思考不会在正文中生成重复的占位说明。
- 图片和文件在对应模型请求首次返回事件后显示读取回执；上传成功本身不会触发回执。回执表示附件已进入获得响应的模型输入，不证明模型正确理解了内容。

## 各层职责

Harness Core 维护通用输入队列，在模型调用之间接收新输入，发出 `user.input.received`、`user.input.applied` 和 `model.input.consumed`。模型输出 ID 包含本轮调用序号，避免同一提供商 ID 在多次调用之间混用。新输入到达时，已开始的工具等待安全点，尚未执行的旧工具调用返回未执行结果并交给模型重新判断。每次新用户输入获得新的模型调用预算，响应序号保持递增。

Agent Host 校验和持久化补充消息、引用与附件，加载授权上下文，提供 `POST /agent-runs/:id/input`，并投影为前端事件。附件回执从实际消息附件计算，不上传重复的二进制内容。未被读取的历史附件在后续有效模型响应时补记回执。后续任务的模型历史按照响应边界和输入实际处理顺序重建。

Frontend 仅根据有序事件显示分段、工具分组、补充消息与读取回执，并维护草稿和可恢复订阅。用户在发送请求期间继续编辑的草稿不会被成功回调清空。Python Sidecar 继续负责附件解析和确定性画布能力，不引入运行编排逻辑。
