# 画布编辑能力与后端样式状态

AI 通过当前能力目录理解可用功能，读取实时文档结构后提交受校验的操作。后端不接收模型生成的任意 CSS、HTML、程序或整份替换文档。

## 分层和唯一实现

| 层 | 职责 |
| --- | --- |
| Harness Core | 通用模型循环、工具和生命周期；不包含简历、画布或页面概念 |
| TS Agent Host | 注册稳定工具，转发 Sidecar 能力，协调活动编辑器请求和实际确认 |
| Python Sidecar | 能力注册表、参数 schema、确定性文档变换、文档与模板持久化 |
| Frontend | 采集活动编辑器快照、展示预览和决定、应用原生编辑事务、自动保存和撤销 |

`editor_operations.py` 的注册项同时提供目录、参数模型、执行器和效果说明。目录 revision 来自实际目录与模板模型的摘要。修改参数或删除能力后，旧 revision 的操作会被拒绝；调用方重新发现能力。

已有样式属性的 schema 直接取实际保存和渲染使用的 `TemplateStyleConfig`。新增样式字段会出现在目录中。新增行为需要在业务能力层注册执行器，这是功能本身的实现；无需继续增加针对单项功能的模型工具或提示词分支。仅增加前端按钮不会自动产生后端能力。

稳定工具为 `resume.read`、`resume.view_pages`、`resume.capabilities`、`resume.inspect`、`resume.edit`。结构读取支持分页、节点原文长度和截断提示，避免把整份简历反复塞入上下文。节点路径随结构变化而变化，结构修改后需要重新读取。

## 支持的操作

| 范围 | 操作 |
| --- | --- |
| 文字 | 精确替换、加粗、斜体、下划线、删除线、局部字号和颜色 |
| 内容块 | 正文与 H1–H3 转换、对齐、行高、缩进、同级移动、插入、删除 |
| 列表 | 正文或列表转换为有序／无序列表，保留嵌套内容 |
| 分栏 | 原文分配到 2–6 栏、统一百分比宽度和栏间距、指定栏对齐、重排和取消分栏 |
| 页面 | 实际页面边距及对应辅助线位置 |
| 模板 | 当前文档的模板样式覆盖，沿用实际模板模型字段 |

分栏按准确原文片段分配，保留原有文字标记，不允许遗漏或编造文字；仅分隔用空白、竖线和中点可移除。多个工作标题可以共用同一栏宽定义，使公司、职位和时间对齐。每批操作在副本上执行，整批校验通过才生成待应用事务。

当前授权资源是打开的简历。`template.style` 优化的是当前简历使用的模板样式，不覆盖共享模板或其他简历。共享模板保存、上下文文件写入、导出等资源操作不能由当前文档的自动修改授权隐式获得。

## 执行与确认

1. AI 查询目录并读取当前编辑器的内容修订和准确目标。
2. Host 再向活动编辑器请求实时快照，包含未保存的手动编辑。
3. Sidecar 校验目录 revision、参数和文档结构，在副本上准备完整事务，不在准备阶段写数据库。
4. 建议模式只返回经过验证的建议。手动应用模式展示效果和真实文档预览，等待用户选择；自动修改模式在当前文档授权内直接执行。
5. 前端应用前校验文档、编辑会话、内容修订、原始文档和有效模板。并发输入、切换文档或模板时拒绝过期修改。
6. 通过 ProseMirror 原生事务应用差异和文档根属性，保留之前的撤销历史，每批修改是独立撤销步骤。
7. 前端立即刷新后端自动保存队列，再回传实际状态与快照。`applied` 表示画布已修改；只有 `persisted=true` 表示后端保存成功。保存失败保留画布草稿并提示重试保存，不能重复执行原事务。
8. Host 等待确认后才向模型返回结果，后续读取和看图重新采集当前状态。截图失败与写入失败分别报告。

保存回写使用编辑器 schema 规范化后比较节点结构，JSON 字段顺序变化不能重置编辑器、增加虚假内容修订或破坏撤销历史。

请求有取消与超时清理。执行前先确认 Host 仍在等待，历史 SSE 重放不能执行写操作。确认包重试幂等，只重传结果；同一前端请求复用执行结果。保存或截图失败不会重复应用事务。

## 后端样式存储

正文标记、段落属性、列表与分栏结构保存在文档 `doc_json`；页面边距保存于 `doc_json.attrs.pageMargins`；当前文档模板覆盖保存于 `doc_json.attrs.templateStyle`。共享模板继续由后端模板仓库存储。样式随文档自动保存、复制和重开，不以浏览器 localStorage 为样式来源。

浏览器只保留未提交的编辑草稿和拖动预览。旧浏览器页边距执行一次性迁移：后端先将原始值与迁移前画布写入 `files/migrations/page-margins`，再保存文档属性，成功后删除旧浏览器键。已有后端设置不会被旧值覆盖；损坏旧值仅备份，不阻止打开文档；备份失败或半写备份不会授权删除原值。

辅助线拖动仅在松手时提交一次后端操作，中间位置作为临时预览。AI 修改与手动样式、列表、标题、边距操作共用 prepare 接口。原生文字输入、选择、输入前的 stored marks 和编辑器拖拽仍由原生编辑器处理，其最终 JSON 通过同一自动保存流程写入后端。

## 验收证据

2026-10-23 使用独立测试数据、本地脚本模型和真实 Chromium，经过真实模型适配器、Host、Sidecar 和前端确认链路完成：

- 个人信息与教育经历四栏，最后一栏右对齐；两条工作标题统一 45/30/25 三栏，职位栏起点均为 x=749px，时间文字右边缘均为 x=1149.5px。
- 成果文字加粗、有序列表转换无序列表、边距 40/40/32/32px、模板正文 14px 与 H2 装饰修改；刷新后恢复四组分栏和全部样式。
- 后端事件记录确认内容修订从 2 到 3，随后实际新页面截图成功返回模型。
- 在独立的前端生产构建中验证自动修改，以及手动确认后的整批撤销、重做、后端保存和刷新恢复；最终执行回执包含 `persisted=true`。
- 采用产品实际画布快照和后端导出接口生成 HTML（130364 字节）及 PDF（68949 字节）；PDF 为一页，提取文字核对原文完整，实际渲染后核对分栏和对齐。

单元与接口测试还覆盖拒绝、取消、跨文档和跨会话、并发输入、目录变更、重复确认、保存失败、观察失败、撤销、复制和迁移备份。脚本模型用于证明系统调用链和约束，不能代替真实模型的语义理解与排版判断质量。
