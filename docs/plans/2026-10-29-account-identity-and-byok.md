# 用户系统与 AI 账号隔离实施方案

日期：2026-10-29。状态：方案已完成讨论，进入可配置实现。

## 1. 已确定范围

| 项目 | 决策 |
| --- | --- |
| 身份服务 | Logto Cloud |
| 进入工作台 | 必须登录，不提供游客入口 |
| 第三方渠道 | GitHub、Google、微信；暂不做手机号 |
| 微信体验 | 满足官方条件时优先免扫码快捷确认，保留扫码与换号 |
| 业务数据 | 按账号保存在本机，包含简历、资料、对话与运行记录 |
| AI 供给 | 用户填写自己的模型 API Key，费用由用户向模型商承担 |
| 当前阶段 | 用户已授权开始编码；尚未创建 Logto，先完成可配置实现 |

Logto 登录身份、模型服务凭据是两类独立凭据。第三方登录不会产生模型 Key 或赠送模型额度。Logto 套餐中的 access token 也不是模型推理 token。

## 2. 建议的完整使用流程

以下是建议默认值，区别于上一节已由用户确定的范围。

### 启动与首次登录

1. 启动先恢复登录状态，确认身份后才展示账号资料，避免闪出上一账号内容。
2. 无有效登录时显示统一登录入口，打开系统浏览器完成 Logto 授权并回到 TypeDance。
3. 第一次第三方授权成功时由 Logto 创建账号，不再要求额外注册一份 TypeDance 密码。
4. 登录后即可使用本地编辑、导入与导出。模型 Key 可稍后配置，首次调用 AI 时再引导。
5. 未配置的登录渠道不展示成可用入口；配置整体缺失时给出明确说明，不提供生产绕过登录的通道。

### 微信免扫码确认

流程：TypeDance 微信入口 → 系统浏览器 → Logto → 微信官方授权页 → 本机微信确认或扫码 → Logto → TypeDance。

- Windows 微信 3.9.11 及以上，已登录且未锁定时，微信官方页面优先提供本机账号快捷确认。
- 快捷确认仍是用户授权，不承诺静默登录或固定只有一次点击。
- 本机微信身份由微信授权页检测；TypeDance 在有效回调与身份验证完成后确认用户。
- 使用 Logto 内置 WeChat Web 连接器，不将移动端 Native 连接器当作 Windows SDK。
- 不关闭官方快捷登录能力；浏览器权限与扫码表现必须实测。
- 详见研究记录中的官方文档与源码。当前尚无真实登录证据。

### 模型 Key 与 AI 使用

- 只使用当前已验证账号的模型配置、密钥、会话和资料。
- 模型 Key 放入系统安全存储；前端只显示是否配置及脱敏摘要。
- A 账号的 Key 不继承给 B；原有共享配置或环境变量 Key 不能静默变成每个账号的密钥。
- Key 不上传 Logto；平台不提供统一模型密钥、不建设平台 AI 额度或扣费系统。
- 通过本机 Agent Host 调用模型，每次运行记录账号归属、实际模型、运行标识与供应商最终用量；估算值单独标识。
- 取消运行后已经发生的用量仍属于原账号，不能转移给新账号。
- 本机保存业务资料不等于本地推理。调用云模型时，本次明确选用的资料会发送给模型服务商。

### 身份绑定

- 内部账号归属以验证后的 issuer 与 subject 为准，不使用昵称、邮箱或前端提供的 userId 作为可信依据。
- 同一 Logto 账号绑定多个第三方身份后，对应同一个本机资料空间。
- 用户从已登录账号主动绑定其他渠道，并完成必要验证；不按同名或同邮箱自行合并。

### 切换账号

1. 冻结新编辑和新 AI 调用，暂停接收新任务，关闭录音与活动事件流。
2. 取消并等待旧账号全部前台和后台运行，拒绝暂停前发出但迟到的编辑请求，然后保存画布；保存失败则保留原工作区、恢复任务入口并允许重试。
3. 卸载旧账号工作区、终止旧请求、撤销旧本机访问能力并清理内存中的敏感资料。
4. 重新认证并使用最终返回的 Logto 身份启动对应资料空间。若仍返回原账号，明确显示实际身份。
5. 健康检查完成后才显示新工作区。失败时保持明确锁定状态或安全恢复原账号，不能身份与资料来源错配。

最近账号列表只帮助选择，不视为登录凭据。旧请求不得因 401 自动取得新账号令牌并重发写操作。

### 会话过期、断网与退出

- 尝试自动续期有效会话，失效时先保存正在编辑的内容，再锁定工作区并提示重新登录。
- 网络失败与明确的身份失效分别处理，不能因网络波动删除账号资料、Key 或未发送输入。
- 建议首次登录、换号、离线重启后的身份恢复要求联网；已打开的有效会话短时断网仍可保存本地编辑。长期离线解锁未在已确定范围内。
- 退出清理本机登录凭据与内存密钥，同时显式撤销刷新凭据并结束 Logto 会话。断网时本机立即退出，远端撤销状态如实报告。
- 默认退出保留本机资料和该账号在安全存储中保存的模型 Key；重新登录同一账号后才可使用，另提供主动删除 Key 的入口。
- 退出 TypeDance 不代表退出浏览器或微信客户端中的上游第三方账号。

### 升级、卸载与重装

- 建议正常升级保留业务资料、账号专属模型 Key 与仍有效的登录状态。
- 建议卸载默认保留业务资料，清理本机登录凭据与模型 Key；彻底删除资料必须由用户明确选择。
- 重装后重新确认 Logto 身份，才可打开该账号保留的资料；已清理的模型 Key 需要重新配置。
- 卸载与重装需要真实检查系统安全存储条目。不能假定删除程序目录会自动清理凭据，异常卸载遗留的凭据也不能作为绕过身份确认的依据。
- 以上为建议默认值，尚未实施或由用户逐项确认。

## 3. 既有本机资料的一次性归属

现有匿名资料不自动分配给首个登录账号。

- 展示当前账号标识与待归属资料数量，提供明确的归入确认与跳过选项。
- 跳过后，资料保留在未归属区，不展示给其他账号，也不复制给每个新账号。
- 归属操作在业务服务停止后执行，维护迁移清单、恢复日志、校验与备份；目标已有冲突数据时拒绝覆盖。
- 归入页单独说明模型密钥迁移及旧明文副本清理；用户确认资料与密钥归属后，再迁入对应的安全存储。暂不归入不迁移密钥。
- 验证新安全存储写入成功后，清理应用管理的旧明文密钥副本，包括旧 auth.json；迁移日志与业务资料备份不得残留该明文 Key。不得修改用户自有环境文件；环境变量只按明确授权的导入规则处理。
- 外部本地文件只迁移引用；不移动、删除或覆盖用户真实文件。
- 迁移完成后运行时代码只使用账号目录，不保留匿名目录读取 fallback。

## 4. 分层设计

| 层 | 本次责任 |
| --- | --- |
| Desktop 协调层 | OIDC 授权与回调、可信身份、安全存储、账号切换状态机、账号独立业务服务生命周期 |
| Frontend | 登录入口、账号设置与切换体验、保存协调、按会话卸载状态，不承担身份或权限的最终判定 |
| TS Agent Host | 当前账号的对话、Run、模型配置与 BYOK 调用；退出前停止全部运行 |
| Python Sidecar | 当前账号的业务数据库、画布、资料引用、文件与导出；本机接口访问控制 |
| Harness Core | 保持通用 Agent Runtime，不加入 Logto、用户套餐、简历或账号目录等业务概念 |

以已经验证的 issuer 与 subject 确定性派生 profileKey，仅用作目录标识。它本身不承担授权；访问授权必须依据当前可信会话与本机访问令牌。账号独立持久化目录、数据库、缓存与检查点。账号切换时重新创建对应业务服务，避免在所有业务表和接口中散落用户筛选规则。

本机接口必须有访问授权及请求来源约束；不能只靠前端隐藏页面或 CORS 隔离。前端请求、保存注册表、事件流和服务访问能力均绑定账号与会话代次。

账号独立目录提供应用内隔离；不将它描述为磁盘内容已经加密，或能抵御同一操作系统用户直接读取文件。数据加密要求需单独明确后设计。

## 5. Logto 与第三方配置准备

1. 建立用于正式用户的 Logto Production 租户；可从 Free 起步，不使用会清理测试用户的 Dev 租户承载正式账号。
2. 租户区域创建后不能直接更改，创建时核对地区；不承诺尚未测量的国内访问质量。
3. 为 TypeDance 创建 Native/public-client 应用，使用外部浏览器、Authorization Code + PKCE、state/nonce 和严格验证的回调。回调地址按最终 SDK/实现登记，不提前虚构固定值。
4. GitHub 选用一种官方连接器并配置对应开发者应用，申请登录所需的最小权限。
5. Google 创建用于 Logto 服务端回调的 OAuth Web 应用；它与 TypeDance 在 Logto 中的 Native 应用是不同配置层级。
6. 微信使用审核通过的网站应用及微信登录权限，授权回调域按 Logto 控制台要求填写。
7. 三家第三方 AppSecret 仅填入 Logto 控制台；TypeDance 客户端不包含这些密钥或管理 API 密钥。
8. 客户端集成只需要公开的 Logto Endpoint、App ID 与批准的回调配置。真实密钥不贴聊天、不写文档、不提交仓库。

本机业务数据与用户自带模型 Key 不交给 Logto 托管。Logto 仍保存账号标识、第三方身份关联和认证相关信息。

## 6. 验收与证据边界

| 类别 | 必须覆盖 |
| --- | --- |
| 身份验证 | 错误 state/nonce、重放回调、错误签名/issuer/audience、过期凭据、未登录接口访问 |
| 第三方真实登录 | GitHub、Google、微信首次注册、再次登录、取消授权、切换身份、返回桌面 |
| 微信快捷登录 | 已登录未锁定免扫码确认、未登录、锁定、用户换号、不同浏览器权限条件 |
| A/B 隔离 | 资料、画布、对话、Key、配置、导出、检查点、草稿、后台任务与审批不串号 |
| 竞态与故障 | 自动保存失败、旧账号延迟响应、401 重试、换号中断、启动失败、断网退出与恢复 |
| 生命周期 | 账号切换后重启、凭据过期、应用升级、卸载与重装、系统安全存储残留、旧资料迁移及迁移中断恢复 |
| AI 真实调用 | 用用户授权的测试 Key 验证当前账号的模型调用和供应商最终用量，不打印或保存测试凭据 |
| 工程交付 | 仓库要求的验证、自查、PR、当前 head 检查、合并与安全同步；客户端发布另行授权 |

单元测试、测试身份服务、真实浏览器、Windows 原生及真实第三方验收分别记录。模拟登录通过不能替代真实微信、Google、GitHub 验收；没有外部配置时准确记录阻塞项。

## 7. 实施顺序

1. 身份验证与安全存储，建立前后端共同的账号会话边界。
2. 双业务服务与全部持久化目录隔离，禁止跨账号重放旧请求。
3. 登录、模型配置、安全退出、换号与会话恢复交互。
4. 既有资料和密钥的一次性归属迁移。
5. 分层回归及完整真实链路验收后，按仓库流程交付。

当前开始上述业务实施，尚未创建任何云资源或完成真实第三方登录。
