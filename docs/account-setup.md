# TypeDance 本机账号

账号、登录状态和绑定关系由当前 Windows 用户管理。TypeDance 不需要部署公网账号服务。邮箱是本机登录名，密码使用 Argon2 保存，恢复码在创建账号或设置密码时显示一次。请保存恢复码。已经绑定 GitHub 的用户也可以先用 GitHub 登录，再设置本机密码。

## 账号与安全

进入工作台后，从左下角账号菜单打开「账号与安全」。可以修改昵称和头像、保存本机登录邮箱、设置或重置密码、绑定 GitHub。绑定后的 GitHub 登录与本机邮箱密码进入同一份工作区。每个 GitHub 身份只归属一个本机账号。

完全退出客户端会结束后台进程。下次启动时，Windows 凭据管理器中保留的本机会话会直接打开工作台。退出登录会清除这份会话。GitHub 登录或绑定需要联网。

## 从旧版升级

升级前，在旧版登录要保留的账号，然后完全退出客户端，保留登录状态。新版会核对系统凭据和旧工作区归属，在应用数据目录的 `account-backups` 下建立备份，再让本机账号继续使用原工作区路径。备份包含简历、模板样式和示例、对话、设置与应用管理的附件。模型 API Key 单独在 Windows 凭据管理器中复制并校验。

迁移失败时，可在错误页重试。旧资料保存在原目录。如果升级前已经退出登录，可回到旧版登录原账号，再重开新版执行迁移。完成迁移后可在「账号与安全」为当前工作区设置密码或重新授权绑定 GitHub。

## GitHub 配置

在 TypeDance 的 GitHub OAuth App 设置中启用 Device Flow。正式构建通过 `TYPEDANCE_GITHUB_CLIENT_ID` 注入公开 Client ID。授权时，用户在 GitHub 页面输入客户端展示的设备码。客户端以 GitHub 的数字用户 ID 确认绑定关系。

`TYPEDANCE_MIGRATION_LOGTO_ENDPOINT` 和 `TYPEDANCE_MIGRATION_LOGTO_APP_ID` 是一次性迁移所需的旧版公开参数，用来定位旧版 Windows 凭据。迁移在本机完成。

开发和测试使用独立的绝对路径 `TYPEDANCE_ACCOUNT_DATA_DIR`。并行启动已安装版与测试版时，需要不同的应用标识和前端开发端口。
