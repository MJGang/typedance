# 人工确认持续等待验证

## 行为与边界

人工应用事务在用户点击前不设截止时间。运行状态和确认卡片明确提示等待用户应用；不会因为等待而产生新的模型调用或重复编辑请求。确认后才开始计算五分钟的实际执行与回传期限，重复开始请求不延长期限。读取画布与自动执行保留超时保护。

等待期间的新要求会结束未确认的旧预览，先处理最新输入。已经确认并开始执行的修改不会因此被重新执行。应用前继续校验文档、编辑会话和内容版本。

进程重启后，旧预览保留在持久化事件中并明确结束，通过“继续任务”恢复检查点、重新读取画布、生成新预览。恢复沿用原运行的修改模式；当前菜单选择自动模式也不会将原手动任务升级为自动执行，界面会显示实际恢复的模式。

本次改动位于 TS Agent Host、跨进程事件契约和前端交互；没有向 Harness Core 添加画布业务，也没有将文档变换或保存规则移入 Host。

## 真实浏览器

使用独立数据目录和端口、真实 Host/Sidecar、Chrome 与 ProseMirror 画布。模型使用受控适配器生成确定的工具调用，不访问外部模型，不接触用户真实简历。

| 场景 | 观察 |
|---|---|
| 等待 467.493 秒后确认，但开发热更新已更换编辑会话 | 请求未因五分钟到期；重新打开对话后按钮仍在。点击时旧事务被会话校验拒绝，正文未覆盖 |
| 稳定会话等待 331.464 秒后确认 | 应用成功，回执 `persisted:true`，版本增加；只将合成正文中的“工作方式：远程”改成“工作方式：混合” |
| 保存后刷新页面 | 正文与预期精确一致，其余文字保持原样 |

两次确认之前均只有最初的四次模型调用，没有因等待追加模型请求。第二次等待后的应用、读取核验、完成与保存均经过实际链路。截图与原始事件摘要保留在本机 `output/playwright/approval-wait/`。

该浏览器验证覆盖合成文本编辑和保存，不代表任意排版操作或外部模型回答质量均已验证。开发热更新更换编辑会话的结果单独记录，没有当作成功应用。

## 自动回归

- 模拟等待三天后仍可显式应用；Host 运行等待十二小时不追加模型调用，确认后继续。
- 实际执行、自动执行和快照读取保留超时；重复开始不重置计时；取消和拒绝不会触发写入。
- HTTP 开始执行验证有效运行与请求；过期请求拒绝执行；未确认的手动请求不能回报已应用。
- 后续输入释放未确认的旧预览；已经开始执行的事务不会被补充输入重新应用。
- 子进程创建 SQLite 与文件检查点后在等待状态被实际终止。新 Host 从磁盘恢复，拒绝旧请求，在新编辑会话生成新的手动预览，确认后完成。
- 前端覆盖等待和执行状态、回执重试不重复修改、拒绝不开始执行、恢复后实际模式及草稿保留。
