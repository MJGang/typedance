# Codex 关键能力补齐验收

基线：TypeDance `12689b2fdd5a4abf8383a496fe66714bf438de2b`；参考 Codex `b4ad33d1a3c10c9652dd57f7afd7a949f8f26895`。能力审计及对应源码见 `docs/plans/ai-capability-audit/findings.md`。

## 初始基线的真实浏览器与模型

使用用户指定的真实凭据调用 `deepseek-v4-flash`。凭据通过测试进程 stdin 临时注入环境，未写入仓库或配置。Web、Host、Sidecar 使用隔离的数据目录和端口，不触及用户实际简历。

测试正文为「张测试 | 前端工程师。熟悉 React 和 TypeScript。」；要求先建三步计划、提问目标岗位，等待回答和手动批准，只替换岗位，其余文字保留。

| 检查 | 实际结果 |
|---|---|
| 原生计划与提问 | 模型调用 update_plan 和 request_user_input；未回答时保持等待，没有修改画布 |
| 刷新展示 | 重新选择原对话后恢复计划、问题卡和运行状态 |
| 停止与 Host 重启 | 原运行分别显示 cancelled / failed；检查点保留，出现显式继续入口 |
| 恢复与答案持久化 | 新 run 先重新 inspect；在后续中断恢复中保留已回答的「AI 应用开发工程师」，无需再次回答 |
| 手动应用 | 提交新事务并等待批准；全场景实际 applied 事务为 1 次，persisted=true，content_revision=1 |
| 最终复查 | 完成前重新获取编辑器快照并调用同一 Sidecar inspect；completion.blocked 携带当前结果，模型收到后再给最终答复 |
| 后端数据 | 通过 workspace-view 读取持久化正文，精确等于「张测试 | AI 应用开发工程师。熟悉 React 和 TypeScript。」 |
| 下一轮历史 | 新运行的模型检查点仍含前轮工具结果及问题答案；一句话准确答复修改内容和保存状态，没有再次请求编辑 |

最终恢复运行耗时 100,601ms（含手动交互）；最后两轮状态 completed。开发期间发现并修复了相邻同标记文本节点导致事务一致性误报的问题；修复前没有应用修改，修复后的真实批准才产生上述唯一一次 applied。

本轮是受控文字编辑验收，不是数小时稳定性基准。所选模型在当前 Host 配置中不支持图片输入，模型如实报告视觉核验未完成；浏览器画布截图用于人工检查，不将其描述为模型已看图。原有长任务压缩实模证据仍见 `harness-long-task-live-2026-10-24.md`。

## 最新主分支集成后的复验

最终分支以 `0a9748f47cad765a6e7d81d2bd8d90ef2290944a` 为集成基线，复用 PR #20 的模型/推理选择、请求统计和会话状态栏，使用当前 `deepseek-flash` 标识与 Off 推理设置再次调用指定真实凭据。

- 独立场景的运行状态依次为 cancelled、completed、completed、completed；问题只实际回答一次，停止后恢复未再次提问，先检查当前状态再申请新的手动批准。
- 实际 applied 仍仅一次，persisted=true。直接以只读方式读取隔离数据库中的持久化画布，正文精确符合预期，canvas version 为 3。
- 恢复运行耗时 79,693ms。页面图起初因隔离进程默认 Edge 路径不可用返回 500，模型明确将视觉复查保留为未完成；指定机器已有浏览器的 TYPEDANCE_CHROMIUM_PATH 后，后续只读运行成功返回真实图片内容并完成模型响应，耗时 9,947ms，没有再次发起写请求。
- 最后一轮还携带前轮编辑和回答的模型工具历史。Host 统一返回当前 document/session/version/revision 元数据，模型确认重新打开后的局部计数变化不意味着内容丢失或保存失败，正文与保存记录一致。
- 会话状态栏持续显示轮次、步骤、速度、Token 和缓存统计；没有另增 model.usage 事件或第二套用量展示。

该阶段文字、图像及跨轮链路均通过；仍不将受控案例扩大为连续数小时的稳定性证明。测试浏览器和服务均已关闭。

## 回归与约束

- 普通跨轮对话直接继承权威模型检查点，包含工具配对和压缩历史；旧无检查点记录只进行一次历史迁移，不能冒充可恢复执行检查点。
- 提问回答在返回确认前写入检查点；跨 run、过期、重复决定被拒绝；新的补充要求可以替代等待中的问题或权限请求，不伪造答案或批准。
- 临时模型故障最多重试 3 次，等待可取消；401/402/无效请求不重试。已有流式输出后失败保留显式失败及恢复入口，不重放部分输出或工具调用。服务端等待超过 60 秒时停止自动重试。
- 编辑复查提供实际状态证据，不宣称自动证明任意自然语言目标或视觉效果；业务数据和文档变换仍归 Sidecar，Core 保持通用。
- 首轮本机全量验证遇到 Windows esbuild 临时文件删除权限错误，隔离 TEMP/TMP 后构建通过；并行启动浏览器期间两项既有列布局测试出现 5 秒超时。最终验收以关闭测试服务后的完整重跑及 PR 当前 head CI 为准。
