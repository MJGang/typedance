# TypeDance 交付

授权与完成标准以仓库根目录 `AGENTS.md` 为准。本技能把实施任务交付到可验收的 PR。

## 开始实施

- 读取仓库约定，确认用户目标、验收条件、受影响层和已有改动。能从代码和上下文确定的细节自行决定；只询问影响结果的缺失决策，并继续不依赖答案的工作。
- 检查 Git 状态、默认分支和远端；从最新目标分支创建 `codex/` 功能分支。已有任务分支可继续使用，避免把本地未合并提交带进新任务。
- 有无关改动时优先用独立 worktree，不 stash、重置或清理用户内容。并行任务各用一个 worktree/分支，确认共享接口与合并顺序；运行服务时隔离端口和数据目录。无需为了小任务自动创建多个 Agent。

## 验证与自查

从当前 worktree 根目录执行（目标分支以实际仓库为准）：

```sh
corepack pnpm verify:change --base origin/main --plan
corepack pnpm verify:change --base origin/main
```

默认范围包含分支提交、已暂存、未暂存和未跟踪文件。只检查提交范围时加 `--head HEAD`。`--plan` 只展示计划，不代表验证通过。

脚本只执行检查，不修改 Git、推送、创建 PR 或自动安装依赖。按 [验证与验收](references/verification.md) 准备环境并补充桌面、交互和导出验收。

检查完整 diff 是否满足目标、保留无关内容、遵守架构边界，修复本次变更导致的问题。用真实运行结果支持结论，不能用静态阅读代替运行证据。

## 提交与 PR

- 验证通过后，仅暂存本次任务的文件或改动块，检查 staged diff，按中文 Conventional Commits 创建 commit。不要使用 `git add .` 收入未知改动。
- 确认 origin 和推送权限，推送功能分支并创建 PR。优先使用 GitHub 连接工具；能力不足时使用已登录的 `gh` CLI。PR 正文遵循 `.github/pull_request_template.md`，描述最终行为、实际验证与待验收项。
- 有现成 PR 时更新同一个。创建或更新后读取当前 head 的检查和评审，修复本次改动引入的失败，重新提交、推送并检查新 head。
- 支持自动评审时使用仓库设置；尚未开启时可在本次已授权 PR 上请求 `@codex review`。不要重复发送相同请求，或宣称仓库文件已开启账户级自动评审。
- 等待期间保持进度沟通。外部权限、配额、环境或已有问题阻塞时提供日志和下一步；重复出现且没有新证据时停止无效重试。没有实际建立后台任务时，不承诺结束会话后仍在跟进。

最终交付 PR 链接、提交标识、验证结果和人工验收项。默认保留 PR 待用户验收，不自动合并或发布。
